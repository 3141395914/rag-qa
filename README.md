# 本地文档知识库问答（RAG）

给一批本地文档建索引，问问题时先检索出最相关的几段，再把这几段和问题一起交给大模型回答，
答案后面标出依据来自哪段资料。

## 运行效果

```
$ python main.py ask "京东自营商品满多少钱免运费？"
正在加载向量模型（第一次会慢一点）...
检索到的资料：
  [1] 相似度 1.000  电商客服\109-188_运费问题.md
  [2] 相似度 0.980  电商客服\126-300_京东自营售后服务.md
  [3] 相似度 0.980  电商客服\984-4356_其他.md

回答：
京东自营商品订单实付金额满 59 元，免基础运费[1]。
```

## 为什么要 RAG

大模型不知道你的私有文档。把整篇文档直接塞进上下文也有三个问题：文档太长塞不下、
token 成本高、上下文太长时模型注意力会被稀释，反而找不准重点。

RAG 的做法是先把文档切成小块存成向量，提问时只把最相关的几块交给模型。
这样既省钱，答案也有出处可查。

## 工作原理

**建索引阶段**：读文档，切成每块 300 字左右、相邻块重叠 60 字，
用 `BAAI/bge-small-zh-v1.5` 把每块转成一个向量，存到 `index/` 目录。

**检索阶段**：两路并跑。向量路把问题转成向量算余弦相似度；关键词路用 BM25 按字面词频打分。
两路结果用倒数排名融合（RRF）合并，取最相关的 4 块。

为什么要两路：向量擅长"意思相近"，但查型号、人名这类细节会模糊；BM25 擅长字面精确匹配，
但换个说法就找不到。两路互补。

**生成阶段**：把这几块和问题拼成提示词，交给 DeepSeek。提示词要求它只根据资料回答、
没有就说没提到、并用 [1] [2] 标出依据。

## 安装与运行

```bash
pip install -r requirements.txt
```

复制 `.env.example` 为 `.env`，填入 DeepSeek 的 Key。

第一次运行需要下载向量模型（约 100MB）。国内网络可以先设置镜像：

```bash
set HF_ENDPOINT=https://hf-mirror.com
```

把要问的文档放进 `docs/` 目录，然后建索引、提问：

```bash
python main.py index
python main.py ask "你的问题"
```

建索引支持增量：每个文件会算一个内容哈希记在 `index/meta.json`，
下次重建时哈希没变的文件直接复用旧向量，只编码新增或修改过的文件。

### 电商客服知识库

```bash
python crawl_jd_all.py
```

爬取京东帮助中心的全部公开条款，共 851 篇，覆盖 86 个分类：
购物指南、订单、配送、支付、发票、售后、账户会员、特色服务等。
脚本支持断点续爬，已经下载的文章会自动跳过。

建索引后可以问：

```bash
python main.py ask "京东自营商品满多少钱免运费？"
```

也可以用网页界面提问：

```bash
python app.py
```

启动后打开 `http://127.0.0.1:7860`，输入问题就能看到回答和引用来源。

### 自写前端版本

`app.py` 是用 Gradio 快速搭的。项目里还有一个自己写的前端：

```bash
python -m uvicorn web:app --port 8000
```

打开 `http://127.0.0.1:8000`。页面用原生 HTML、CSS、JavaScript 写在 `static/index.html`，
后端是 FastAPI，`POST /ask` 接收问题，返回答案和引用来源。

## 目录结构

```
config.py     模型名、切块参数、检索条数等配置
chunker.py    把长文档切成小块，切点尽量落在句号或换行处
embedder.py   加载本地向量模型，把文字转成向量
retriever.py  建索引、保存索引、按余弦相似度检索
bm25.py       关键词检索打分，补上向量检索的字面短板
reranker.py   重排序模型，把问题和段落拼在一起判断相关度
generator.py  拼提示词，调用 DeepSeek 生成答案
main.py       命令行入口
app.py        网页界面，用 Gradio 做的
web.py        FastAPI 后端，配合 static/index.html 使用
static/       自己写的前端页面
crawl_jd_all.py  爬取京东帮助中心全部条款
docs/         放要检索的文档
index/        生成的索引，不进仓库
```

## 已知限制与下一步

- 目前 851 篇文档、4841 块，覆盖京东帮助中心的大部分公开条款。
- 切块按固定长度切，没有按标题或语义切分，长文档里可能把一段完整论述切断。
- 重排序只对混合检索的前 20 条做，平衡了精度和延迟。
- 向量模型和重排序模型都跑在 CPU 上，文档量大时建索引和检索都会变慢。
- RAG 不适合统计和精确筛选。问"有多少条款提到运费"，它只能基于检索到的几段回答，
  不像 CSV 过滤能遍历全量数据。结构化查询应该交给 CSV 或数据库。
